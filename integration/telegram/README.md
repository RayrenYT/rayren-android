# Telegram → Rayren: тестовый автоимпорт 0.1.7, 23.10.2026

Рабочий пилот использует `rayren_app_feed.py` и `rayren_app_bot.py`: личная команда `/rayren` в существующем боте выдаёт секретную ссылку на 90 дней. Она открывает `import.html`, затем приложение, где пользователь подтверждает импорт. Основные серверы и доступный Cups попадают в одну группу «Мой Rayren»; новые ссылки того же аккаунта обновляют группу без дублей.

Сервер читает существующие привязки и права через SQLite `mode=ro`, а хеши новых ссылок хранит отдельно в `rayren-app-access.db`. Команда `FeedStore().revoke(telegram_id)` отзывает ссылки этого пользователя; применять только к явно выбранному аккаунту. Веб-выдача `/incy/rayren-app/<secret>` возвращает строго данные владельца секрета. Полный сценарий и ограничения — `docs/BUILD_REPORT_0.1.7.md` в корне проекта.

Проверки: `python -m unittest discover -s integration/telegram -v`; HTTP-тестам нужен Flask. На RU1 временные тестовые базы создаются в `/dev/shm`, чтобы не нагружать диск. Не включать реальные секреты и клиентские базы в примеры, репозиторий или исходный архив. Серверная установка выполняется с резервными копиями и проверкой исходных SHA-256; APK содержит только клиентский обработчик формата.

## Отложенный вариант: одноразовая привязка устройства

Реализован и тестируется локальный модуль одноразовой привязки устройства
`account_pairing.py`. Он не запущен на сервере и пока не подключён к APK.
Это начало интеграции, не готовый вход через Telegram.

## Сценарий

1. Android генерирует 32 случайных байта, кодирует base64url без padding:
   `verifier`. SHA-256 ASCII-строки, hex lowercase — `challenge`.
2. HTTPS POST `/api/app/pair` с challenge → `create()` → случайный code на 180 секунд.
3. Приложение открывает `https://t.me/<имя_существующего_бота>?start=app_<code>`.
   Telegram получает одноразовый code, но не verifier и не постоянный ключ устройства.
4. Бот в личном чате показывает подтверждение «Подключить Rayren на устройстве?».
   Только после нажатия вызывает `approve(code, update.effective_user.id)`.
   Не принимать Telegram ID из HTTP-запроса или текста /start.
5. Android POST `/api/app/exchange` с code+verifier. Пока нет подтверждения — pending;
   после — одноразовая выдача device token на 30 дней. Хранить в Android Keystore vault.
6. GET `/api/app/feed` с Authorization Bearer → `feed(token, lookup)`.
   Основная подписка и отдельный Cups возвращаются по действующим правам этого пользователя.
   DELETE `/api/app/device` → `revoke`.

## Подключение к существующему боту

Локальная копия `ru2-migration-20261014/bot-after-ru2-final.py` содержит
`get_sub_id`, `_subscription_link`, `_incy_subscription_link`,
`_telemost_profile_for_telegram`, `billing_store.entitlement`.
Это ориентир для адаптера, а не проверенная текущая версия production.
Перед установкой сверить живой код и схему базы.

`lookup(telegram_id)` обязан заново проверить срок/статус доступа и владение основной
подпиской; вернуть HTTPS-источник с постоянным id `main`. Cups возвращается только при
действующем персональном членстве, например через `_telemost_profile_for_telegram`.
Отсутствующий Cups — пустой profiles; ошибка базы — ошибка запроса, не пустой ответ.
Не принимать имена/профили другого пользователя из клиентского запроса.

## Что ещё нужно для работающего входа

- HTTPS HTTP-адаптер с лимитом тела, rate limit по IP и устройству, без записи
  Authorization/code/verifier/ответов в журналы. approve не публикуется наружу.
- Обработчик /start и кнопка подтверждения в существующем боте.
- Android: экран привязки, ограниченный опрос только пока экран открыт, защищённое
  хранение token, подтверждение полученного аккаунта и атомарная синхронизация
  управляемых подписок. Ручные подписки остаются независимыми.
- Смена аккаунта/выход/отзыв: удалить только управляемые им подписки и токен.
  Обычные ручные данные не удалять. Не переиспользовать отозванный Cups.
- Проверить на двух тестовых Telegram-аккаунтах: основная подписка; основная+Cups;
  просроченный доступ; отзыв устройства; невозможность получить чужую подписку.

Тесты: `python -m unittest discover -s integration/telegram -v`.
SQLite хранит хеши code/token, challenge, числовой Telegram ID и сроки. Это отдельная
база привязок; платежи, комнаты и существующие подписки модуль не изменяет.
Заявки ограничены 1000 активными; внешнее ограничение частоты всё равно обязательно.

Основание формата Telegram-ссылки:
[официальная документация](https://core.telegram.org/bots/features#deep-linking).
