# Исправление импорта · 0.1.1-alpha · 17.10.2026

## Результат

`Rayren-0.1.1-alpha-arm64-v8a.apk`, Android 8.0+, ARM64, applicationId `com.rayren.android`, versionCode 2. Подпись APK v2 проверена и совпадает с 0.1.0: обновление устанавливается поверх первой версии. Размер APK около 99 МБ. Контрольные суммы APK и соответствующих исходников — `artifacts/SHA256SUMS.txt`.

## Причины и исправления

- HTTP URL раньше попадал в парсер ключей серверов и вызывал «Неподдерживаемый протокол». Общий resolver теперь направляет HTTP, HTTPS и Rayren deep link в загрузчик подписок. Android разрешает явно заданные legacy HTTP URL; в диалоге показано предупреждение о передаче ключей без шифрования.
- Одна ссылка из сообщения с подписью бота распознаётся без ручного удаления подписи. Если ссылок несколько, приложение просит вставить одну, а не выбирает её молча. JSON и URI серверов с вложенными HTTPS-адресами остаются конфигурациями.
- JSON INCY/3x-ui использует сокращённые `settings.address/port/id/flow`, а первая версия ожидала `vnext[].users[]`. Поддерживаются обе записи; аналогично поддержаны сокращённые VMess/Trojan/Shadowsocks. Серверы преобразуются через прежнюю проверяемую модель. Удалённые inbounds/routing/logging не запускаются.
- Одна строка Hysteria2 с `obfs=salamander` останавливала импорт всей обычной подписки. Теперь Salamander преобразуется в `streamSettings.finalmask.udp`, а пароль маскировки и SHA-256 сертификата сохраняются. Та же проверка применяется к JSON. Неизвестные маски и повреждённые pins отклоняются, а не молча удаляются. Сохраняются ALPN, REALITY spiderX и ML-DSA verification key.
- Существующая серверная выдача выбирает JSON по маркеру `Happ/` в User-Agent. Клиент явно идентифицирует себя как `Rayren/0.1.1 Android (Happ/JSON-compatible)` и отправляет `Accept: application/json, text/plain;q=0.9`. Это согласование поддерживаемого формата, без подмены URL, правки сервера и обработки внешних правил Happ.
- В экспортируемом журнале есть этап ошибки и безопасный код, например `IMPORT_FAILED_DOWNLOAD_HTTP_500`. URL, токены, тело ответа и сообщения сетевых исключений не записываются.

## Проверка на реальных данных

Предоставленные основные HTTP и HTTPS endpoints `/rayren/` в прежнем формате периодически отвечали HTTP 500. При ответе 200 обычная подписка содержала 8 VLESS и 1 Hysteria2 с Salamander/pin; именно эта строка выявила дополнительную ошибку парсера. Первоначально `/incy/` также вернул 500, затем отдавал 200.

Финальная проверка с теми же JSON-совместимыми заголовками, которые отправляет приложение: основная HTTP, основная HTTPS и INCY дали HTTP 200. Ответ каждого endpoint передан в исправленный JVM-парсер через stdin без сохранения ключей на диск. Каждый импортировал 9 уникальных профилей: 8 VLESS и 1 Hysteria. Для каждого создана общая конфигурация Rayren. Обезличенные результаты — `artifacts/live-json-import-verification.txt`. Это проверка импорта и генерации конфигурации, не проверка подключения к девяти серверам. Серверная инфраструктура не менялась; доступность сервера остаётся внешним условием.

Пользователь сообщил, что OpenFlux работает на его телефоне с Android 16. Все три native `.so` нового APK побайтно совпадают с 0.1.0; OpenFlux, olcRTC, Xray и HEV в этом исправлении не пересобирались.

## Проверка пользователем

Установить 0.1.1 поверх прежней версии, сохранив профиль OpenFlux. Добавить основную HTTPS-ссылку из сообщения бота; подходят также основная HTTP и ссылка «для INCY». Проверить появление серверов, выбрать знакомый VLESS вручную, подключиться и открыть сайт. Проверить сохранённый OpenFlux отдельно. Если сервер подписки снова вернёт 500, APK должен показать именно HTTP 500, а существующие профили должны остаться.

Установка обновления, Android UI/TUN и реальные Xray-подключения нового APK на телефоне исполнителем не проверены. Остальные ограничения alpha из предыдущего отчёта и `REQUIREMENTS_STATUS.md` сохраняются.
