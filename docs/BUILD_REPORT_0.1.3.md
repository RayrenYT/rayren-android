# Rayren 0.1.3-alpha · проверка 18.10.2026

Package com.rayren.android; versionCode 4; Android 8+, target 36; arm64-v8a. Изменения — FOLLOWUP_0.1.3.md. APK предназначен для обновления поверх 0.1.2 без удаления хранилища.

## Проверки

Итоговая чистая сборка успешна. Все 100 JVM-тестов пройдены, ошибок/пропусков нет. Android lint: 0 ошибок, 2 предупреждения (DiscouragedApi и ChromeOsAbiSupport). Все перечисленные ниже native-проверки пройдены. Подпись APK v2 проверена; SHA-256 сертификата `8d4945113b6a4f4c971103b4b723a985001ce1a89e2e90e3694dbbaf56420c31` совпадает с предыдущей версией. Проверка ZIP alignment 16 KiB пройдена.

- Domain: 88 тестов, включая состав Smart Balance, безопасный fallback, сохранение общего сервера в нескольких подписках, имя без секретного URL, формат уведомления, этапы замера и повторную проверку нового балансировщика.
- App: 12 тестов, включая HTTPS-импорт, запрет перехода HTTPS → HTTP, сохранение старой подписки при ошибке, блокировку одновременных сеансов провайдера. Итого 100 JVM-тестов.
- Нативная библиотека пересобрана с ProbeReport. Полное время HTTPS GET сохраняется; дополнительные поля содержат только длительности.
- Реальный Xray принимает 19 конфигураций, включая новый leastPing/observatory.
- Функциональные локальные тесты: VLESS → проверенный HTTPS, перехват DNS, блокировка после остановки core; DIRECT/BLOCK при неисправном прокси; балансировщик с неисправным первым узлом и рабочим вторым; передача неизвестного домена удалённому прокси при неработающем DNS клиента.
- DoT: положительный TLS через SOCKS, отклонение недоверенного сертификата и неверного пароля, жизненный цикл.
- Новый HTTPS-замер: GET с искусственной задержкой ответа, сохранение задержки в полном времени, запрет небезопасного URL, запрет redirect и недоверенного сертификата.
- Чистая сборка Android и lint; счётчики и точные контрольные суммы — artifacts/verification.txt и SHA256SUMS.txt.

При старте Smart Balance наблюдений ещё нет: первый запрос может попасть на proxy fallback. Если он не отвечает, Rayren сохраняет тот же core и повторяет запрос, пока observatory выбирает живой узел. Общий бюджет первоначальной проверки группы ограничен двумя таймаутами, максимум 30 секунд. Показывается задержка успешного HTTPS-запроса, не суммарное время поиска маршрута.

## Локальный TLS и антивирус

Первые положительные HTTPS/DoT-тесты падали с unknown authority/PKIX/EOF, как в предыдущей сборке. Проверка на 127.0.0.2 воспроизвела проблему; ::1 запрещён текущей сетевой конфигурацией Windows. На тестовых серверах включён **необязательный** запрос клиентского сертификата (RequestClientCert / requestClientAuth). Клиенты не предоставляют сертификат и по-прежнему проверяют единственный доверенный тестовый корень. После этого локальная инспекция не мешает тестам. Настройки антивируса не менялись, доверие к постороннему корню не добавлялось, insecure TLS не использовался. Изменение касается только тестовых серверов.

## Границы

ADB не обнаружил подключённых устройств. Визуальная проверка Compose, реальный VPN-трафик, переключение маршрутов на Android, сравнение задержки с Happ и островок Vivo/Samsung через LiveBridge ещё не проверены на физическом телефоне. Исправление уведомления основано на формате, который распознаёт исследованный LiveBridge; его разрешения/фильтры на телефоне APK не меняет.

Smart Balance импортирует состав proxy-узлов, а стратегию задаёт Rayren (leastPing). Произвольные сторонние правила, настройки leastLoad и исходные DNS/API из JSON не переносятся. В уведомлении показано имя группы Smart Balance; отдельных одновременно используемых узлов UI пока не перечисляет.
