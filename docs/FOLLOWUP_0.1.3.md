# Rayren 0.1.3-alpha · изменения 18.10.2026

Обновление по шести замечаниям пользователя. Физического устройства в ADB нет; сравнение пинга с Happ и островок Vivo/Samsung требуют проверки пользователем.

1. **Пинг.** Сохранён HTTPS GET через прокси к `https://www.gstatic.com/generate_204`, с новым соединением, проверкой сертификата, ожидаемым статусом 204 и запретом перенаправлений. Для Xray убрано принудительное разрешение целевого домена через дополнительный DoH-запрос: имя передаётся удалённому прокси. Настройки предпочтения IPv4/IPv6 по-прежнему явно разрешают адрес; OpenFlux/olcRTC сохраняют ForceIPv4 внутри Rayren, чтобы их SOCKS-адаптер не передавал DNS в ОС. DNS приложений через TUN сохраняется. Цифры не масштабируются. В журнал добавлены total/socks/tls/response длительности без адресов и ключей. socks — этап до TLS; TLS может включать ожидание установления удалённого транспорта. Это не отдельный точный замер DNS сервера.
2. **Обход VPN.** Единственный вход в настройки сайтов и приложений. Здесь .ru/.рф, автоматические группы, свои домены и выбор установленных приложений вручную. Повторный пункт .ru/.рф из режима маршрутизации убран; старое значение переносится в соответствующий переключатель при открытии/сохранении настроек. Существующие исключения сохраняются.
3. **Режимы.** Три сегмента с иконками: «Авто», «По пингу», «Ручной». Объяснения открываются по значку информации.
4. **Подписки.** Серверы показаны внутри сворачиваемых групп. У группы есть название, количество, дата обновления, переименование и проверка пинга всей группы. Общие серверы видны в каждой владеющей подписке; вручную добавленные выделены отдельно. Имена из profile-title поддерживают base64. Адрес с секретным путём не выводится в заголовок. Ручное обновление заново получает тело подписки, чтобы ранее потерянный балансировщик восстановился даже при прежнем ETag.
5. **Smart Balance.** JSON-балансировщики с минимум двумя разными поддерживаемыми proxy outbounds сохраняются отдельными профилями. Селекторы ограничивают участников; freedom/direct не становятся участниками. Балансировщик Rayren использует Xray leastPing и observatory, до 32 узлов. Внешние routing/DNS/API и fallback не исполняются; fallback только первый proxy, никогда прямой интернет. Обычные серверы также сохраняются. Это отдельная функция от режима «По пингу», который выбирает один профиль на уровне приложения. Активный маршрут в интерфейсе/уведомлении называется Smart Balance; отдельный узел может изменяться между соединениями.
6. **LiveBridge.** В постоянное уведомление возвращены реальные скорости ↓/↑ в распознаваемом формате KB/s, включая нули при простое, и контекст VPN. Сохранены сервер, задержка, действие пинга и отключения. Заголовок Rayren стабилен, стандартный BigTextStyle, category SERVICE, прежние канал и ID. В исследованном коде LiveBridge VPN без скоростей может скрываться. Это исправляет формат источника; доступ к уведомлениям и правила самого LiveBridge остаются настройками телефона.

## Проверка после установки

Установить поверх старой версии без удаления. Во вкладке «Серверы» нажать обновление: балансировщик появится, если подписка его содержит. Выбрать сервер с известным результатом Happ, проверить одинаковую сеть и один адрес HTTPS gstatic. Для сравнения отключать другой VPN; повторить несколько раз. Сверить сервер, пинг и скорость в шторке, затем островок LiveBridge на обоих устройствах. Проверить обход вручную выбранного приложения и смену сервера без выключения VPN.

При расхождении пинга нужен экспорт журнала: новые этапы позволяют отличить задержку TLS/транспорта от ожидания HTTP-ответа. Ссылки с ключами не нужны.
